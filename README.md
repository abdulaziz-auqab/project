# موقع البورتفوليو — دليل النشر

هذا المجلد جاهز للنشر على GitHub Pages كما هو.

```
index.html        صفحة البورتفوليو (إنجليزية)
cv.pdf            السيرة الذاتية — يفتحها زر CV في الموقع
assets/           لقطات المنصة (بيانات عرض توضيحي لجهة خيالية)
demo/             ضع هنا النسخة التجريبية من منصة ADKAR
.nojekyll         يمنع GitHub من معالجة الملفات، لا تحذفه
```

---

## أولًا: النشر (من المتصفح، بلا أوامر)

1. سجّل الدخول في github.com ثم اضغط **New repository**.
2. سمِّ المستودع `USERNAME.github.io` بحروف اسم المستخدم نفسها، واجعله **Public**، ثم **Create repository**.
3. في الصفحة التالية اضغط **uploading an existing file**، ثم اسحب محتويات هذا المجلد كلها (ليس المجلد نفسه — بل الملفات والمجلدات التي بداخله).
4. اضغط **Commit changes**.
5. من تبويب **Settings ← Pages**: اختر Branch = `main` و Folder = `/ (root)` ثم **Save**.

بعد دقيقة إلى دقيقتين يصير الموقع على `https://USERNAME.github.io`.

> إن أردت رابطًا باسم آخر، سمِّ المستودع مثلًا `portfolio` بدل `USERNAME.github.io`، ويصير الرابط `https://USERNAME.github.io/portfolio/`.

### تحديث الموقع لاحقًا

ادخل المستودع، افتح الملف، اضغط أيقونة القلم، عدّل، ثم Commit. أو استخدم **Add file ← Upload files** لاستبدال ملف كامل.

## ثانيًا: إضافة النسخة التجريبية من منصة ADKAR

الموقع مُعدّ لهذا مسبقًا: في صفحة دراسة الحالة بطاقة **Try the demonstration build** تظهر **تلقائيًا** بمجرد وجود الملف، وتبقى مخفية إن لم يكن موجودًا. فلا حاجة لتعديل أي شيفرة.

الخطوة الوحيدة: ضع ملف المنصة داخل مجلد `demo` باسم `index.html` بالضبط.

```
demo/index.html
```

ثم ارفع المجلد إلى المستودع. الرابط سيصير `https://USERNAME.github.io/demo/`.

## ثالثًا: قائمة فحص قبل رفع النسخة التجريبية

النسخة المنشورة على الإنترنت يراها أي شخص، بما فيهم محركات البحث. راجع هذه النقاط في الملف قبل رفعه:

**البيانات**
- [ ] لا توجد أسماء منسوبين حقيقيين في أي وحدة أو تقييم أو سجل فريق
- [ ] حزمة البيانات المحمّلة هي حزمة العرض التوضيحي للجهة الخيالية، لا بيانات العمل
- [ ] لا توجد ملفات مزامنة لأعضاء الفريق (ملفات JSON المحفوظة داخل التطبيق أو بجواره)
- [ ] بنك الرسائل والقوالب خالٍ من خطابات حقيقية أُرسلت فعلًا
- [ ] سجلّ الخطابات الصادرة فارغ

**الهوية**
- [ ] اسم الجهة وشعارها وألوانها من الحزمة الخيالية
- [ ] صور الأختام والتوقيعات محذوفة تمامًا، لا محمية بكلمة مرور فقط
- [ ] ترويسة الخطاب لا تحمل شعار الجهة الحقيقية ولا رقمها

**المحتوى الداخلي**
- [ ] دليل المخاطبات الرسمي: إن كان وثيقة داخلية معتمدة، فالأفضل إبقاء آلية التدقيق وتفريغ نصوص القواعد وأرقام صفحاتها من قيم توضيحية
- [ ] لا كلمات مرور ولا اعتمادات محفوظة داخل الملف
- [ ] بيانات الوصف داخل مخرجات PDF وWord لا تحمل اسم مؤلف حقيقي

**قبل النشر**
- [ ] افتح الملف في المتصفح وجرّبه كما لو كنت زائرًا: أنشئ خطابًا، صدّر حزمة، افتح كل لوحة
- [ ] ابحث داخل الملف نصيًا عن اسم الجهة وعن ثلاثة أسماء أشخاص تعرفها، وتأكد أن النتيجة صفر

**نقطة إدارية:** المنصة بُنيت في سياق عمل حكومي. نشر نسخة تجريبية منها للعرض المهني أمر معتاد، لكن الحصول على موافقة شفهية من المشرف على المركز قبل النشر يحميك، ويصير في ذاته نقطة تُحسب لك أمام جهات مثل الشركات الاستشارية الكبرى التي تنظر إلى التعامل مع المعلومات كجزء من تقييم المرشح.
